# Mining Site / Quarry — GoDigital Reverse Engineering v1

This quarry is the provenance layer for the first GoDigital reverse-engineering baseline.

A quarry is **source material**, not canonical architecture.

The purpose is to preserve enough evidence that future architecture statements can be traced back to repositories, branches, commits and paths instead of relying on memory or assistant-generated citations.

See `GD-RE-Q01-source-corpus-ledger-v1.0.md` for recovery anchors.

## Evidence discipline

Each durable claim should prefer:

```text
repository
branch
commit SHA
path
blob SHA when captured
observation
interpretation
confidence
contradiction/supersession
```

Temporary ChatGPT/tool citation identifiers must not become long-term provenance.

## Source hierarchy

Preferred evidence strength:

1. executable code and domain schemas;
2. service contracts and integration calls;
3. configuration and deployment manifests;
4. tests and fixtures;
5. branch/commit history;
6. dependency manifests;
7. README/documentation statements;
8. remembered intention.

This hierarchy is not absolute; contradictions should be recorded rather than silently reconciled.

## v1 intent

Reverse Engineering v1 is the first documented recovery pass. It may later be superseded by v1.1/v2, but this version should remain historically available rather than being overwritten or deleted.
